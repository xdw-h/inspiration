# 本地灵感记录 H5 设计方案

> 版本：v1.1  
> 日期：2026-08-18  
> 状态：已确认，待实施计划

## 1. 产品目标

实现一套面向手机使用的个人灵感记录 PWA。用户可以使用文字或语音快速记录灵感，在浏览器支持语音识别时获得自动转写；不支持或转写失败时，仍可保存和播放原始录音。

应用采用完全本地方案，不需要账号、后端或云端存储。所有灵感、录音、标签和转写文本均保存在当前手机浏览器中，通过 ZIP 文件完成备份和换机恢复。

## 2. 设计原则

- 记录优先：录音和文字先保存到本地，不等待转写。
- 原音保留：转写结果不能替代或覆盖原始录音。
- 能力降级：浏览器不支持语音识别时，录音功能仍然可用。
- 离线可用：首次加载后可离线打开应用、记录、查看和播放内容。
- 明确风险：提示用户浏览器数据可能被清理，并引导定期导出备份。

## 3. 范围

### 3.1 首版包含

- 文字灵感的新建、查看、编辑和删除。
- 语音录制、暂停、继续、结束、试听、重录和保存。
- 浏览器支持时进行语音转写，并允许人工修正。
- 标题、正文、标签、收藏和灵感状态。
- 关键词搜索及按类型、标签、状态、收藏筛选。
- 本地草稿、离线启动、存储保护和应用锁。
- 包含 JSON 与音频文件的 ZIP 备份和恢复。

### 3.2 首版不包含

- 账号体系、后端服务和跨设备自动同步。
- 云端语音转写及对所有手机的转写兼容保证。
- 公开分享、社区、评论和多人协作。
- AI 扩写、摘要、知识图谱和复杂统计。
- 付费订阅与商业化功能。

## 4. 参考项目结论

技术实现参考 `D:\money`：

- 沿用 Vue 3、TypeScript、Vite、Vue Router 和 Pinia。
- 沿用 Dexie 管理 IndexedDB，并通过版本迁移维护数据结构。
- 将图片附件的独立 Blob 存储模式改造成音频附件存储。
- 沿用 Service Worker、Web App Manifest、存储持久化申请和 PWA 更新机制。
- 将 JSON 与图片的 ZIP 备份机制改造成 JSON 与音频文件备份。

新应用应改进参考项目中页面直接访问数据库的情况。页面只调用仓储和业务服务，由仓储负责 IndexedDB 事务、级联删除和数据迁移。

## 5. 技术架构

### 5.1 技术栈

- Vue 3 + TypeScript + Vite：应用框架与构建。
- Vue Router：首页、新建、详情、标签和设置页面。
- Pinia：页面会话状态、筛选条件、录音状态和提示信息。
- Dexie + IndexedDB：灵感、标签、录音 Blob、草稿和转写文本。
- MediaRecorder API：录制手机麦克风音频。
- Web Speech API：在浏览器支持时进行语音识别。
- Service Worker + Manifest：离线启动和添加到手机桌面。
- JSZip：本地数据及音频的导出和导入。

### 5.2 模块边界

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| `ideas` | 灵感增删改查、搜索和筛选 | Repository |
| `recorder` | 权限、录音、分片、暂停和恢复 | MediaRecorder |
| `transcription` | 能力检测、识别状态和文本修正 | Web Speech API |
| `storage` | IndexedDB、配额、持久化和迁移 | Dexie |
| `backup` | ZIP 导出、校验和恢复 | JSZip |
| `privacy` | 应用锁和隐私提示 | Web Storage、Web Crypto |
| `pwa` | 离线缓存、安装和版本更新 | Service Worker |

## 6. 页面与导航

底部导航采用五段对称结构：“灵感”“时间轴”“新增”“标签”“设置”。中央新增按钮参考 `D:\money` 的实现上浮约 24px，导航底板在按钮周围形成柔和的圆弧包裹；两侧各两个等宽入口，当前页使用珊瑚色图标、文字和短指示线。

底栏使用完整矢量轮廓或等效 CSS 遮罩形成连续曲线，不使用简单矩形底板叠加圆形按钮。底栏需适配手机安全区，所有入口保持至少 44px 点击范围，圆弧不得遮挡页面内容。

### 6.1 灵感首页

- 顶部提供搜索框和筛选入口。
- 默认按最后更新时间倒序展示灵感卡片。
- 卡片显示标题、内容摘要、类型、标签、收藏、状态和更新时间。
- 无标题时从正文或转写文本生成安全摘要。
- 空状态提供“记录第一条灵感”操作。

### 6.2 新建记录

- 点击新增按钮后选择文字记录或语音记录。
- 文字模式提供正文、可选标题和标签。
- 语音模式打开底部录音面板，显示录音时长、状态和主要操作。
- 录音结束后支持试听、重录、补充文字和保存。
- 离开页面或进入后台时保存文字草稿和已产生的音频分片。

### 6.3 灵感详情

- 展示并编辑标题、正文、标签、收藏和状态。
- 语音灵感提供播放器、时长和原始录音信息。
- 转写文本与用户正文分开保存，允许人工修正。
- 删除需要二次确认，并在同一事务中删除关联录音和转写结果。

### 6.4 标签与设置

- 标签页支持创建、重命名、排序和删除标签。
- 设置页提供转写能力状态、存储用量、存储保护、应用锁和备份恢复。
- 设置页明确说明卸载浏览器、清理站点数据或换手机可能造成数据丢失。

### 6.5 时间轴

- 按创建日期倒序组织全部文字和语音灵感，日期列、时间轴节点和内容卡片形成三列结构。
- 每张卡片展示类型图标、标题、摘要、标签和本地格式化时间；语音灵感使用麦克风图标区分。
- 相邻日期通过连续细线连接，当天内容优先显示“今天”，其他日期显示 `YYYY-MM-DD`。
- 点击卡片进入现有灵感详情，不复制编辑、播放或删除逻辑。
- 空状态提供返回“新增”按钮，筛选结果为空时保留当前筛选条件并给出清除入口。

## 7. 录音与转写流程

1. 用户主动点击录音后申请麦克风权限。
2. 根据 `MediaRecorder.isTypeSupported()` 选择当前浏览器支持的音频格式。
3. 录音过程中定期产生 Blob 分片，并暂存在 IndexedDB 草稿中。
4. 用户结束录音后合并分片，立即保存音频附件和灵感记录。
5. 若浏览器支持语音识别，则保存识别结果；否则将转写状态设为“不支持”。

转写状态包括 `not_supported`、`idle`、`listening`、`completed`、`failed`。转写失败不影响录音保存、播放或备份。

浏览器强制中断录音时，应用保存已收到的分片并提示“录音被系统中断”。麦克风权限被拒绝时，说明开启方式并提供文字记录入口。

## 8. 本地数据设计

### 8.1 数据表

| 表 | 关键字段 |
|---|---|
| `ideas` | `id`、标题、正文、类型、状态、收藏、创建和更新时间 |
| `audioAssets` | `id`、`ideaId`、Blob、MIME、时长、大小、创建时间 |
| `transcripts` | `id`、`ideaId`、文本、状态、是否人工修改、更新时间 |
| `tags` | `id`、名称、颜色、排序、创建时间 |
| `ideaTags` | `ideaId`、`tagId` |
| `drafts` | 输入内容、音频分片、最后保存时间 |

录音 Blob 不写入 `ideas`，避免读取列表时加载大文件。灵感与附件的创建、更新和删除必须通过事务保持引用一致。

实现说明：`ideaTags` 作为逻辑关系保留，物理存储采用 `ideas.tagIds` 的 IndexedDB multi-entry 索引，避免额外关系表；搜索和标签级联删除均通过该索引完成。

### 8.2 时间规则

数据库内部使用 ISO 8601。界面统一通过共享格式化工具处理：

- 日期显示为 `YYYY-MM-DD`。
- 日期时间显示为 `YYYY-MM-DD HH:mm:ss`。
- 列表明确只需分钟时显示为 `YYYY-MM-DD HH:mm`。
- 有时区的时间先转换为用户本地时区。
- 空值或解析失败显示 `-`，不显示 `Invalid Date` 或原始 ISO 值。

## 9. 备份与恢复

导出 ZIP 包含：

- `manifest.json`：备份版本、生成时间、灵感数和音频数。
- `ideas.json`：灵感、标签、关系和转写文本。
- `audio/`：以附件 ID 命名的原始音频文件。

导入前完整校验版本、JSON 结构、ID 唯一性和音频引用。校验失败时不改变现有数据。恢复时默认跳过相同 ID，并展示导入、跳过和失败数量。

大体积备份导出前显示预计大小。存储空间不足时保留现有数据和草稿，并提示先导出备份或删除不需要的录音。

## 10. 日期、错误和隐私处理

- 只在用户点击录音后请求麦克风权限，不在启动时申请。
- 不上传文字、录音、标签或使用数据。
- 转写能力不可用时明确显示“当前浏览器不支持自动转写”。
- 录音失败需说明发生位置、可能原因和可执行的恢复操作。
- 所有破坏性操作二次确认，清空全部数据需要额外确认。

## 11. 测试与验收

### 11.1 单元与集成测试

- Repository 的增删改查、事务回滚和附件级联删除。
- 录音能力检测、MIME 选择、分片合并、中断和权限拒绝。
- 转写支持、失败、人工修正及不覆盖正文。
- ZIP 导出导入、重复 ID、损坏音频、缺失引用和版本不兼容。
- 日期覆盖 ISO、毫秒及时区、普通数据库时间、空值和解析失败。

### 11.2 移动端验收

- 在 375px、390px、430px 宽度下无横向溢出。
- Android Chrome 与 iPhone Safari 能录制、试听、保存和离线重开。
- 微信内置浏览器不支持转写时仍能保存录音，并显示降级说明。
- 刷新、关闭后重开和短暂离线不会丢失已保存内容。
- ZIP 能完整备份并恢复灵感、标签、转写文本和音频。

## 12. 实施边界

首个实现计划应按以下顺序拆分：项目骨架与 PWA、本地数据层、文字记录、录音、转写降级、搜索标签、备份恢复、隐私与完整验收。任何阶段都不得引入后端依赖。
